# Assessment demo recording

Target length: three to four minutes. Use a fresh account and the built-in fictional scenarios. The initial plans and every subsequent update must be approved before describing them as applied.

## 0:00–0:30 — Explain the workflow

Sign in and show the events screen.

Say: “Event managers receive updates in conversation, but need a consistent operational plan. Xperience turns those messages into proposed changes. The manager reviews and approves them, and the dashboard computes the resulting risks.”

Point out the clearly labeled scripted demo. Explain that the same workflow supports live Gemini after adding an API key.

## 0:30–1:40 — Wedding journey

1. Select **Try wedding scenario**. Show the proposed sessions, vendor requirements, tasks, and example dates. Approve the initial proposal.
2. Show the overview, tasks, and schedule. Explain that unknown vendor capacities are not assumed to be confirmed.
3. Expand **Try a scenario update** and send the Sangeet venue confirmation. Review the venue status change and completed confirmation task; approve it.
4. Send the 150 travelling guests update. Approve and show accommodation/airport-transfer requirements.
5. Send the catering deadline update. Review the date seven days before the Wedding Ceremony; approve it.
6. Send the Reception photographer update. Show the proposed unavailable status and replacement task, approve, and point out the Reception coverage alert.

Say: “The system keeps the source of each update visible and connects problems to the affected work.”

## 1:40–2:45 — Corporate changes

1. Return to **Events**, then choose **Try corporate scenario** and approve its initial plan.
2. Send and approve the resort confirmation and 40 travelling employees updates.
3. Send the Friday activities deadline; show its explicit resolved date before approving.
4. Send and approve the CEO’s day-two attendance update. Show the leadership session on the second day.
5. Send and approve the transport vendor’s 150-person capacity update. Show the **50-person transport shortfall** and the task to arrange extra vehicles.
6. Open the transport vendor, change available capacity to 200 and status to confirmed, and save. Show that the factual shortfall clears.

## 2:45–3:30 — Trust and implementation

1. Open **Activity** and expand one approved change to show before/after values.
2. Generate a proposal, edit the event name manually before approving, then reopen the proposal. Explain why its revision is stale and why approval is disabled.
3. Reload the page to show saved state.
4. Briefly mention Next.js, Express, MongoDB, JWT, and Gemini, and show the README’s setup/test commands.

Say: “The language model proposes; validated application code applies. Each approval is atomic, account-scoped, and revision-checked.”

## Before recording

- Hide real credentials and unrelated windows.
- Keep the API and MongoDB running.
- Use the exact configured application URL.
- Decide whether to demonstrate scripted mode or real Gemini; describe the chosen mode accurately.
- Check that recording resolution makes task labels and proposal changes readable.
- Record the actual screen with your preferred recorder. This repository supplies the script, not a pre-recorded video.
